# Patient Application-CDS Rejection

**Release context (2026-10-13):** stable 2.1.0 ships the Maven tooling and
accepted packaging-inclusive PetClinic result. Provisional 2.15 adds Patient
Java 26/Leyden benchmark evidence, with failed original calibration admitted by
exception and unqualified or failed performance bounds; no new Maven binaries.
See [current release boundaries](../releases/current-state.md).

Historical decision: dynamic Patient application CDS was blocked for the tested
single-replica deployment.

Fixed-artifact archive-economics screens and the extracted-layout common-class
study failed their frozen admission rules. No favorable archive was selected
after failure. This decision does not reject CDS generally:

- Patient stock JDK base CDS is confirmed at `-8,279 KB` median PSS;
- Patient no-CDS is independently confirmed at `-8,903 KB`;
- Doctor application CDS is confirmed for its own artifact/archive protocol.

The distinction is whether an artifact-specific Patient application archive is
mapped over the stock base archive.


The 2.15 Patient benchmark uses a later Java 26/Leyden configuration with its
own per-artifact caches. It is a separate provisional result, with failed
original calibration admitted by exception and unqualified or failed costs;
this older rejection neither invalidates nor fully qualifies that experiment.
