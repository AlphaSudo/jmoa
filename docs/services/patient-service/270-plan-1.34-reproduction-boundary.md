# Plan1.34 public reproduction boundary

The source branch will identify the exact optimizer and transformation recipe. The private Patient application, owned caches, response bodies and infrastructure configuration are not distributed. Public paired summaries and hashes permit aggregate checking; they do not allow an independent service reproduction without those authorized inputs.

`270-plan-1.34-public-result-schema.json` defines the minimum public result. A future clean result must also publish all82 costs, null precision, source/build/cache/runtime/workload identities, assumptions, failures and cleanup. External raw reanalysis is not external replication. No successful result is supplied in this schema.

A reproducible evaluation requires: an authorized application source/artifact; an exact public optimizer commit and pinned build tools; a semantic workload/response oracle; same-feature B0/candidate materializations; each arm's own compatible cache; declared host/cgroups/native policy; fresh passing8 controls and24 confirmation units. The final runner's dry-run and actual CLI qualification must precede any advertised evaluation command. At this intake stage, no target-launch command is represented as qualified.

The public claim remains scoped to processPSS after the defined workload. Synthetic stroke, ConfigClient intent, line-number observability, ambient cache and performance bounds are explicit gates/boundaries, not inferred from a smaller JAR.
